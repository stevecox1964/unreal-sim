## What was done this session

- Traced agenda/place resolution through `_execute_world_action`, `_execute_routed_walk`,
  `UnrealBridge.execute_action`, and C++ `HandleCommandMoveTo`. The engine already performs a
  synchronous path test and reports `path: none|partial|full`, `moved`, path length and endpoint gap.
  No new bridge API, C++ change, plugin build, or authored entrance graph was added.
- Inspected the existing world DB without changing its place records. It already contains learned
  `Don's Donuts` owned places for both Dufus and Maren, as well as the broader community label
  `Don's Donuts building with large donut sign`. The old resolver allowed that community label to
  override the learned positions. The coordinates are remembered locations, not verified entrances.
- `_resolve_place_endpoint` now prefers the owned-place store, whose existing matching logic ranks
  authored/learned/wake-seeded entries and owner preference. Community-only names use the recorded
  survey stand point when present, otherwise the old center, with `PLACE_EXTENT_CM` (900 cm).
  The survey district itself is no longer the arrival region.
- `_execute_routed_walk` retains its method name but now sends the final place anchor directly to
  the existing engine pathfinder. It no longer generates grid-center legs or a box-edge standoff.
  `_routes` now stores destination, target XY, extent, path status and distance progress; it no
  longer stores `path`/`leg`. Changed targets/extents refresh the cached destination.
- Added `route_planner.at_place`, a shared square-containment check. Schedule and movement arrival
  agree, including a place extending across a district boundary. Known-place travel/arrival no
  longer requires the current observation to carry grid coordinates. Grid indexing remains in
  the existing storage model; unbounded worlds still cannot resolve grid-indexed place anchors.
- Named moves record `_resolved_target` for movement tracing. Missing current position returns an
  explicit error. Unknown names retain the existing unresolved-name idle behavior.
- Engine `none`/`partial` results remain visible and are narrated as blocked/incomplete approaches,
  not arrival. Scheduled directional movement can perform local recovery after those results or
  when stuck; ordinary scheduled travel still resolves to the named goal.
- Agenda/schedule prompts now describe place progress and path status. Necessary detours may
  temporarily increase straight-line distance. Survey maps remain contextual background without
  fabricated grid-route overlays; their text reports the actual place distance/bearing even when
  agent and destination share a district.
- Added `doctrine/place_travel.md`; Dufus and Maren import it instead of the survey-era `ground.md`.
  It allows purposeful visits indoors and into unfamiliar ground, requires observed evidence for
  access and claimed actions, and distinguishes an old survey refusal from present accessibility.
  The inactive surveyor retains `ground.md`. Shared movement doctrine now allows necessary detours.
